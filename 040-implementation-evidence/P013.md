## Scope and design decisions

P013 implements the §5.1 authoritative session-acceptance transaction: validate the immutable session input, idempotency key/hash, and host-session ceiling; under one `BEGIN IMMEDIATE` transaction count live reservations and atomically insert `exec_sessions(state=creating)`, lifecycle sequence 1, the create idempotency record, and one `exec_capacity_reservations` row. A same controller/operation/key with the same canonical hash returns the existing session without a second reservation; a changed hash returns an idempotency conflict. Live reservations remain counted until a later confirmed-cleanup transaction; no runtime callback or shell start is performed before or inside acceptance.

The existing P012 `CreateSession` API remains a compatibility fixture path while the new acceptance method is the production-shaped idempotent create boundary. The migration contains the reusable `exec_idempotency` shape scoped to `create_session`; later P015 will extend mutation lookup/use without adding a second table. Capacity defaults to the selected 20 active sessions per authority, with an explicit test/configuration override for deterministic fixtures.
