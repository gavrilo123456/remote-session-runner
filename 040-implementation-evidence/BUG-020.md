# BUG-020 — bounded persistent-shell control-channel loss

## Scope and incident evidence

Source authority is the Mac checkout at
`/Users/tomasz.walczuk/projects/remote-session-runner`, branch `dev`.
The starting source revision is
`8783d0b7dd80807188f4a5c936575a4eaab1957d`; its parent is the BUG-019 policy-loop
fix `01384e7`. The worktree was clean before this repair.

On 2026-10-14, a fresh native read of the original SlideStudio outbox found
`req-codex-validate-cached-logger-v8-lineage-20261014-1442` terminal at revision
`4`: command `cmd-1ae80e89d973712eff853aa1f8ce13c2`, session
`sess-358ce473737f104517d3f22dfc6f53d6`, `complete` / `lost`, incomplete output,

The advertised event prefix was contiguous and had exactly one terminal
`command_lost` at `2026-10-14T16:02:38.903616Z`, about 30 minutes and 2.7 seconds
after `command_started`. No private event text was printed.

This disproves the current indefinitely-active disposition. It does not prove
the historical child exit or descriptor condition. The exact incident cause
remains unconfirmed. Both serving Mac processes subsequently attested revision
`01384e7109c3c97b2975ffb7a913cc9d9c279a57` through `/health/ready`.

The source regression addresses a concrete static defect: an inherited control
descriptor can keep a blocking frame read open after the owned Bash dies;
forced cancellation previously waited for that read's execution mutex. The
correction must terminate conservatively without replay and preserve the
existing proof-based cleanup and retained-capacity boundary.

The first two full Ubuntu invocations failed three existing `runnerlocal`
external-mailbox fixture tests on both architectures. Moving `TMPDIR` beneath
a private directory alone did not fix them. Inspection found the actual cause:
Go 1.27.1 creates the individual `t.TempDir()` directory with `0777` masked by
the test process's umask. Both selected Ubuntu shells reported `0002`, yielding
a group-writable fixture trust root that correctly fails the external-mailbox
safety policy. Every other package passed.

The three exact failures passed in a focused check after applying `umask 077`
only to the test shell. The next full invocation exposed why changing the
whole suite's umask is unsuitable: existing negative lifecycle-lock and
controller-map fixtures intended to be `0644` were masked to `0600`, making
those tests incorrectly construct safe files. That invocation was not counted
as a validation pass.

The final correction is nine lines of **test setup only** in the three P158/
P165 positive fixtures: explicitly `os.Chmod` their `t.TempDir()` trust roots
to `0700`. No production path validation, negative fixture, host ancestor mode,
or persistent account setting was changed. The Mac focused gate passed with
`umask 0002`, reproducing the normal Ubuntu setting, and the final Mac full
suite passed again. Ubuntu validation returns to each host's normal settings.
The task-owned private directories from the earlier attempts were removed by
EXIT traps after the test processes exited; Go caches/module caches were
reused throughout.
