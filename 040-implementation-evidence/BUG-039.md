## Behavior and proof boundaries

The existing authority still decides whether a request ID is already bound.
Only its `ErrMailboxExchangeConflict` result enters the new path; canonical
retries and new-ID idempotency conflicts keep their existing behavior.

The importer now:

1. Preserves the exact newer input, empty marker and sanitized conflict
   diagnostic in private `conflicts/<request_id>/<input_sha256>/` files.
2. Makes that evidence and a bounded unfinished-work index durable before
   marker-first, fingerprint/inode-checked withdrawal.
3. Rechecks the immutable original authority binding before cleanup, leaving
   response, event, ACK and capacity records untouched by this operation.
4. Resumes interrupted withdrawal before ordinary unmarked-draft collection.
5. Marks completed withdrawal with a durable `retired` artifact and removes
   only its unfinished index entry. Idle recovery does not scan archive history
   or sync an empty pending directory.

The conflict diagnostic uses `request_id_conflict`, `accepted: false` and
`executed: false` for the **newer publication**, not for the original exchange.
It contains no submitted script or idempotency key. Full newer bytes remain
in the private archive; the original outbox is never replaced with a rejection.

The native client also rejects `WriteRequest` when an existing visible outbox
response or ingress diagnostic reserves the ID (`ErrRequestIDRetained`).
Existing result reads and ACKs remain available. This early presence check
does not replace the server's authority, guarantee detection of a concurrently
appearing result, or authorize ID reuse by direct file writers.

There is no new database schema or incident-specific production switch.
Independent source review found no blocking issue after the durability and
empty-index performance checks were addressed.

## Disposable regression coverage

response/events/ACK, native `0600` and workspace `0644` inputs, canonical
formatting retries, accepted originals, mailbox namespace isolation, and
independent fresh work proceeding despite a replacement race.

Interruption cases include archive/index publication, marker staging and
processor restart before old-draft collection. Negatives cover changed
fingerprints/bindings, private-directory/file tampering, symlinks, permissions,
and preservation failures leaving the conflicting pair untouched. Recovery
reads only a bounded unfinished index, including the valid request ID
`pending`, which cannot collide with the internal `.pending` directory.
