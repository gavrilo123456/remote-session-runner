## Results

### Implementation

- Added audit action `runtime_cleanup`, outcome `failed`, and reason `runtime_cleanup_unconfirmed`. Migration 23 rebuilds the append-only audit table with the additional constrained event type while preserving prior rows, index, and triggers.
- A failed session-runtime cleanup now commits a `lost` session/lifecycle record where possible, retains the session reservation, increments cleanup health, and appends a correlated safe audit record without logging raw errors, scripts, output, or credentials. Storage errors and cleanup errors remain wrapped for callers and health accounting.
- A failure to commit `ready` after runtime startup now invokes runtime cleanup. When the failure also prevents the cleanup outcome from being committed, the session remains durably `creating` with its reservation pinned for recovery; it is not reported ready or released.
- On a streaming post-start output-persistence error, execution immediately sends a bounded runtime command-cancel request from the failed persistence callback, then attempts runtime-session shutdown. It records `lost` only if that durable transaction commits; while SQLite remains locked/full, the existing `running` command, `busy` session, and live slot remain unchanged and output is not claimed complete.
- Added actual-authority fault injection shared by Mac and Ubuntu, bounded to 512 additional SQLite pages (2 MiB) plus a temp directory. Its `SQLITE_FULL` case fills the disposable DB and session B-tree; lock cases use a 100 ms test busy timeout. No host storage is filled.
- Added a P22-to-P23 migration test which retains an existing audit row and append-only trigger and accepts the new cleanup-failure row.
