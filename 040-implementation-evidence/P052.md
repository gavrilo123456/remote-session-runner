## Planned deliverable and gates

1. Extend `RunnerdForwarder.Handle` for `run_or_resume_job` and `get_job` only; the bridge remains an adapter with no scheduling, persistence, or shell logic.
2. Preserve the bridge frame's stable `resource_id` as the private `job_id`, forward the same idempotency key and request ID, preserve exact script bytes, execution target, environment, and optional source/limit/isolation/policy fields, and carry stable one-off `session_id`/`command_id` values when supplied. For legacy/minimal frames without those two additive fields, derive deterministic IDs from the stable job ID so retries cannot allocate replacements.
3. Forward job reads by the payload job ID with the authenticated server-side controller query; never synthesize a Mac intent/projection outcome in the bridge.
4. Add fake authoritative run/read fixtures covering stable retry bodies, all one-off IDs/keys/script, mapped controller, teardown/result payload preservation, read identity, malformed/oversize script rejection, and transport uncertainty.
5. Run focused P052 tests, full Mac hermetic/vet/build/smoke/race/format/diff gates, synchronize and verify Mac/GitHub/Ubuntu equality, then run the named Ubuntu P052 bridge suite. Close evidence only after the host gate passes.

## Unresolved assumptions

- The v1 bridge schema requires environment, remote execution target, and script for `run_or_resume_job`; additive source/limits/isolation/policy and stable session/command IDs remain optional for backward-compatible frames.
- The private runnerd API requires stable job, session, and command IDs. Explicit IDs are authoritative when present; deterministic `jobID`-derived values are used only when an older/minimal bridge frame omits them. No ID is inferred from script bytes or target text.
- P052 forwards run/read only. Cancel/close and event streaming remain P053–P054; queued Mac never-delivered job reads remain Mac ingress behavior in later phases.

## Implementation results

**Status: PASS**

- Extended `RunnerdForwarder` for `run_or_resume_job` and `get_job` only.
- Run forwarding preserves the bridge `resource_id` as `job_id`, the same idempotency key and request ID, exact script bytes, environment, execution target, optional source/limits/isolation/policy payloads, and explicit stable one-off `session_id`/`command_id` values. Minimal older frames receive deterministic child IDs derived from the stable job ID, so a retry cannot allocate replacement resources.
- Job reads use the private runnerd job route and controller query built from the authenticated server-side SSH-key mapping. The bridge does not invent Mac intent or projection state for a never-delivered job.
- Authoritative run replies preserve shell failure and teardown fields as result data; private transport uncertainty remains the bridge `transport_uncertain` error path.
- Added fake run/read fixtures for stable retry body identity, mapped controller, exact script/source, child IDs, command failure plus teardown outcome, derived IDs, malformed payloads, and oversize-script rejection before HTTP forwarding.
