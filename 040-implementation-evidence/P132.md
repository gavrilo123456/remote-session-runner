- P132 design intent: Linux systemd sends SIGTERM to `runnerd`; the process must stop admitting new API work, stop new dispatch, drain accepted work within a bounded interval, cancel remaining active sessions through the normal execution/runtime state path, verify committed audit/event state, then close resumable HTTP event streams and owned listeners/socket within the systemd stop budget. Both ingress routes share the same execution service, Linux runtime, and authority database. No container, tunnel, or alternate execution account is introduced.

## Implementation and validation plan

- Linux composition-root coordinator wiring uses an 8-second drain and three 4-second cleanup stages (cancel, flush, close). The versioned unit sets `TimeoutStopSec=30s` and `KillMode=mixed`, so runnerd receives the initial stop signal and can cancel its Bash sessions before systemd kills any remaining service processes. The host gate asserts both settings.
- Preserve in-flight event followers through command drain and durable audit/event checks, then close streams at a resumable cursor and remove only the private socket owned by this process.
- Cancel every still-active Linux session through the normal `execution.Service.CloseSession`/runtime process-group cancellation path. Preserve lost state and capacity when cleanup cannot be confirmed; do not manufacture a successful terminal command.
- Add hermetic coordinator/listener/request-admission tests and an opt-in real-host P132 gate. The host test must run only after its tested Mac commit has been pushed and fast-forwarded to Ubuntu, use the configured mTLS identity and pinned SSH identity, keep all temporary fixtures outside the checkout, restore the prior binary and systemd unit if the gate fails, leave the service active, and preserve the authority database. A narrow test cleanup helper releases only this test's lost reservations after validating the fixture record, confirming its recorded PID is absent, and checking the service cgroup.
