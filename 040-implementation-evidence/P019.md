## Planned deliverable and gates

1. Add a durable `exec_command_slots` reservation table with a four-live-slot default; cancellation, timeout, and loss retain a slot until confirmed stop/teardown.
2. Add one atomic scheduler claim that selects the oldest eligible session/authoritative command ordinal, enforces one running command per session and host slot capacity, persists `command_started`, and moves the session to `busy` in the same transaction.
3. Add idempotent slot inspection/release for confirmed stop and deterministic fake-clock multi-session fairness/no-starvation and race fixtures. P019 does not start a real runtime; P020+ owns fake runtime orchestration.
