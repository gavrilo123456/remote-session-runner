## Planned deliverable

- Add a Mac session-runtime adapter over the existing process adapter and use the shared `execution.Service`; do not introduce a second execution engine.
- Add `runner-locald`'s owner-only Unix-socket HTTP server and `/internal/v1/accept-intent` endpoint.
- Reload the committed intent from SQLite by ID, verify canonical request hash and submit ordinal, reject remote targets and non-local controllers, and decode execution metadata from the committed payload.
- Reject unknown/forged request fields, including caller-provided `script`, and bound the serialized request before any authority/service call.
- Add focused private-socket, committed-bytes, forged-payload, hash, ordinal, restart/reopen, and target checks. The named host gate is the synchronized Ubuntu focused P060 suite; this phase does not claim Runner application HTTPS readiness or remote execution.

P061 remains the later private read/cancel/close/event-subscription phase, and P062 remains the Mac real-account/source-provenance gate. P143 remains a future approval gate: if physical power-cut testing is unavailable, a software-crash-only durability claim requires explicit user approval and must not be inferred from P060.

## Implementation and Mac gates

- Added `src/internal/runnerlocald` with the owner-only Unix-socket server and `/internal/v1/accept-intent` handler. The handler bounds the serialized body, rejects unknown fields, reloads the immutable `LocalIntentRecord` by ID, verifies the canonical request hash and submit ordinal, rejects remote targets/non-local controllers, and passes the stored script bytes and metadata into the shared `execution.Service`. It never accepts script bytes from the request body.
- Added `MacSessionRuntime`, which adapts the existing Mac process adapter to the shared session/command runtime interfaces. No second execution engine was introduced. `runner-locald` now loads the owner-only Mac config/database/environment registry, wires the shared service, and serves the private socket.
