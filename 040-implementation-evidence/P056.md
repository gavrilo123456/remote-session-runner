## Planned deliverable and gates

3. Classify local pre-send failures, post-send/no-reply uncertainty, remote bridge error frames, and command failures as distinct errors. A nonzero command result remains a bridge reply, not an SSH transport failure.

## Implementation and hermetic gates

- **Implementation:** PASS. Added `src/internal/sshclient/client.go` and focused tests. The client invokes OpenSSH through an argument vector with `-F /dev/null`, `IdentitiesOnly=yes`, strict pinned host-key checking, disabled global known-hosts/config fallback, no PTY, no forwarding, explicit identity/user/host/port, and the fixed `runner-ssh-bridge --stdio` command. The spaced Mac pin path is quoted inside the `-o UserKnownHostsFile=...` value.
- **Bridge framing:** PASS. Added production request encoding and bounded reply decoding to `sshbridge`; request validation happens before starting a mutation transport, both directions use the one-MiB ceiling, replies must have the expected protocol/envelope/request ID, and stream replies require a terminal `stream_end` unless the bridge returns an error frame.
- **Mutation identity:** PASS. `Call` sends the caller's request/resource/idempotency IDs and payload unchanged on each fresh SSH process; retrying the same `RequestFrame` therefore preserves the stable mutation identity. No client-side ID regeneration or target fallback exists.
- **Transport/error boundary:** PASS. `TransportError` distinguishes `before_send` and `after_send` phases and wraps `ErrTransport`; bridge `response_type: "error"` replies are returned as data with no transport error. Stream loss and nonzero SSH exit after request delivery are reported as post-send transport uncertainty.
- **Mac focused tests:** `go test ./src/internal/sshclient -run '^TestP056' -count=1 -v` — PASS; bridge package tests including P049–P054 — PASS.

## Named two-host P-NET-01 gate

- **Host/account and pin:** Mac client connected directly to `129.151.232.40` as `ubuntu`, with `-F /dev/null -l ubuntu -i .../dispatcher_ed25519 -o IdentitiesOnly=yes`, and the pinned `ssh_known_hosts` file. The dispatcher key was verified unauthorized before fixture installation and after cleanup; the Mac SSH config/development key could not be a fallback.
- **Temporary host fixture:** outside Git at `/home/ubuntu/.local/share/remote-session-runner/p056-host-fixture`. A temporary owner-only Python protocol helper was forced by one `restrict,command=".../bridge.py" ssh-ed25519 ... runner-mac-dispatcher-p056` entry. It validated the fixed original command, rejected PTY, derived the response controller from the authenticated fixture mapping `(queued_mac, tomasz.walczuk)`, rejected forbidden controller fields, and returned bounded NDJSON replies. This was a transport/authority fixture, not a Runner application or command-execution test.
- **Positive client framing:** a real Mac `sshclient.Client.Call` `ping` succeeded and the reply carried `authenticated_controller: {controller_type: queued_mac, controller_id: tomasz.walczuk}` from the server-side fixture mapping.
- **Stable mutation retry:** the same `submit_or_resume_command` frame was sent in two fresh SSH exchanges with request ID `host-mutation-1`, resource ID `host-command-stable`, and idempotency key `host-idempotency-stable`; both replies matched and the fixture observed the stable identity.
- **Event stream:** a real Mac `Client.Stream` replay received the event and `stream_end` frames in order.
- **Changed host key:** a temporary wrong-key known-hosts file caused strict host verification failure; the client returned a `TransportError` (`after_send` because OpenSSH accepted local pipe bytes before terminating). No reply was accepted.
- **Alternate identity:** a newly generated unauthorized ED25519 identity, with the user SSH config bypassed, failed to authenticate and returned `TransportError` (`after_send`). The dedicated dispatcher key remained the only accepted fixture identity.
- **Alternate command:** requesting `sh -c id` with the dedicated key returned rc 126 and `p056 forced command denied`.
- **PTY:** `ssh -tt ... 'runner-ssh-bridge --stdio'` returned rc 255 and `PTY allocation request failed on channel 0`.
- **TCP forwarding:** a temporary sleeping forced wrapper allowed a local channel attempt through `-L 127.0.0.1:34568:127.0.0.1:22`; the listener accepted the local TCP connect, while SSH reported `channel 2: open failed: administratively prohibited: open failed`, proving the forwarding channel was denied.
- **Forged controller:** a raw bridge frame containing a forged controller payload produced the fixture reply `response_type:"error"`, code `controller_field`, message `controller is server derived`, with rc 0 and no user output on bridge stderr.
- **Restoration:** the original Ubuntu `authorized_keys` was restored and the entire fixture directory removed. Final checks showed mode `600`, owner `ubuntu:ubuntu`, fixture absent, and the dedicated dispatcher key failed again with `Permission denied (publickey)`.
