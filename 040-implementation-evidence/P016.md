## P016 deliverable

1. Validate the authoritative command sequence before allocating another ordinal. Existing rows must start at ordinal 1 and contain no gaps; a corrupt/gapped sequence fails closed.
2. Expose a read-side per-session eligibility query. Terminal predecessors (`succeeded`, `failed`, `cancelled`, `timed_out`, `rejected`, `lost`) are skipped; the oldest queued command is eligible; an earlier `running` or `cancelling` command blocks later work; non-ready/terminal sessions have no eligible command.
3. Keep P017’s general event append/replay and terminal state/event transactions, and P019’s host scheduler/slot fairness, out of this phase. P016 only establishes the durable order and eligibility boundary used by those later phases.
