## Existing implementation inventory

- Store schema is version 20 with migrations through `0020_idempotency_expiry_warnings.sql`; no audit schema or structured audit package/records were found under `src`.
- Authoritative create and submit acceptance are already transactional in `store.AcceptSessionCreate` and `store.AcceptCommand`; Mac local requests are accepted transactionally in `store.AcceptLocalIntent`. Cancel and close first authorize against the stored controller, then durably accept idempotency in `store.EnsureIdempotency`.
- Shared policy/action methods are in `execution.Service` (`CreateSession`, `AcceptCommand`, `CancelCommand`, `CloseSession`). Mac Unix and mailbox ingress are in `localapi`; the Mac worker is `runnerlocald`; SSH bridge and direct mTLS ingress are in `runnerd` and `runnerd/direct_api.go`.
- Existing real-host gates are `p124twohost` for Mac/Ubuntu CLI and transport coverage and `p117twohost` for direct public mTLS. Neither is an I-07 audit acceptance test yet. The preflight TLS probe is not a Runner application test.
- Audit ingress labels will be set only by trusted server adapters, not accepted from request bodies. Successful records should commit with the associated durable acceptance. Denials should be recorded with a bounded reason code and no request body/error text. Structured logs should contain only the same safe fields as the audit rows.
