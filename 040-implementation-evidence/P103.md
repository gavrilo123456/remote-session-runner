## Implementation and test approach

The Router already distinguishes a before-send transport error from a post-send uncertain result and reconciles the latter by stable resource identity. The current mailbox processor republishes uncertain receipts as `accepted` indefinitely: it has no deadline check even though terminal mailbox storage already supports immutable `indeterminate`. P103 will close that behavior gap and add an end-to-end hermetic fake-transport test through the actual mailbox files and projector. The test will also cover a stream interruption followed by cursor-based recovery, with no duplicate resource or execution.

## Implementation review

- Added a shared 24-hour `store.DefaultRemoteUncertaintyWindow` and wired the mailbox processor to the same duration used by Router reconciliation. The processor uses an injected clock for deterministic tests and rejects a negative window.
- When an accepted remote mutation remains durably uncertain through the full window, the file response becomes terminal `indeterminate`. It contains the already allocated stable resource IDs and `delivery_state: uncertain`; it does not claim remote acceptance/rejection or invent target state/output. Terminal mailbox storage keeps that response immutable.
- Added a hermetic local API test with a fake transport covering proven before-send non-delivery, remote commit followed by reply loss, stable-ID/key GET_JOB reconciliation without resending the mutation, contiguous event-prefix persistence and cursor resume after stream loss, same-key mailbox retry, and the 24-hour indeterminate deadline.
- Corrected the never-delivered `run` response in the implementation and adjacent P100/P101 expectations to `rejected` with `runtime_unavailable`, without the unsupported `teardown_outcome: not_created`. The design permits `not_created` only when the target authoritatively confirms that the run never created a job; local proof that a send did not happen is not such a target outcome.
- Reviewed the complete implementation diff, P103 test, and neighboring assertion changes. `gofmt -d` and `git diff --check` returned no output.
