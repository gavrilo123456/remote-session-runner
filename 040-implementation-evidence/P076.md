## Implementation

- Added schema migration `0012_remote_projections` for separate Mac remote session and command projection tables. The tables retain immutable remote identity, authoritative state/output metadata, source, capabilities, `observed_at`, and `is_stale`; they have no foreign keys or write path into `exec_sessions`/`exec_commands`.
- Added `store.RemoteSessionProjection` and `store.RemoteCommandProjection` upserts and reads. Upserts validate remote identity/capabilities, reject immutable identity conflicts, ignore older observations, and preserve the last snapshot when a stale marker is set. Explicit stale-mark methods never change authority or `observed_at`.
- Added dispatcher parsing for complete remote result snapshots. Rich replies are persisted after remote acceptance/reconciliation; sparse legacy acceptance fixtures remain accepted without inventing authoritative state. Event-mirror failures mark an existing command projection stale.
- Added local API projection resources for accepted/reconciled remote session and command intents. Before target acceptance or before a projection exists, reads remain `local_intent`; after projection persistence, reads expose `view: projection`, remote authority, observed fields, capabilities, and stale status.
- Added focused store, dispatcher, and local API fixtures for monotonic observations, stale marking, immutable conflicts, complete remote snapshots, and authority/projection read separation.
