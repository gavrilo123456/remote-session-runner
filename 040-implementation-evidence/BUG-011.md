## B011-P3 Mac source result

Added the Mac implementation of the existing two-stage lost-runtime adapter
contract. `MacSessionRuntime` now implements `execution.LostRuntimeRecoverer`
and forwards Stage A and Stage C to `MacProcessAdapter`; the shared execution
service remains the sole owner of proof ordering, paired command-slot/session
reservation release, and no-replay behavior.

Stage A reads the owner-only marker, validates the selected account, UID,
session, generation, workspace, PID/PGID, and in-memory process identity. For
a runnable group it also verifies the live Darwin process-start identity before
it can signal. It uses a Darwin `libproc` process-group snapshot. A runnable
group may contain only the one exact,
current-adapter Bash root. Any descendant, foreign member, malformed marker,
account or generation mismatch, unavailable process information, or missing
current-adapter shell handle leaves capacity retained and sends no signal.

Darwin lists an unreaped child in its process-group list while returning
`ESRCH` for that child's BSD-info lookup. The adapter treats that exact listed
absence as non-runnable, then reaps it only through the original
`PersistentShell`/`cmd.Wait` handle. A zero-length BSD-info response without
`ESRCH` is uninspectable and fails closed. The bounded Mac stop path takes a
fresh exact-root snapshot immediately before TERM and again before KILL. The
operating system has no atomic validate-and-signal-group operation, so the
code documents that narrow scheduling boundary and retains capacity whenever a
recheck observes an extra or mismatched member.

Stage A writes `LostRecoveryCleanupConfirmedAt` atomically while preserving
the owner marker and workspace. A retry with that stamp returns before any
PID inspection or signal. Stage C validates only the retained marker,
generation, account, and proof, then removes the owned workspace and marker;
it does not inspect or signal the old PID. No generic Mac reconciliation or
schema behavior changed.

Added these isolated Darwin tests:

- `src/internal/runtime/bug011_lost_recovery_mac_darwin_test.go`
- `src/internal/runtime/bug011_lost_recovery_mac_nocgo_test.go`

They use only temporary `0700` workspaces and test-owned Bash/sleep children.
They prove reaping an owned zombie, bounded cleanup of an exact live root,
retention without a signal for an actual Bash-started child, retained capacity
for generation/account/UID/start/PID/PGID/session/malformed-marker failures,
retention by a fresh adapter that lacks the original wait handle, safe
post-proof finalization retry, and both Stage A and Stage C replacement-PID
no-signal behavior. The no-cgo Darwin test fails explicitly so this coverage
cannot silently disappear. No test uses a repository command, network,
mailbox, installed service, real state database, credential, or live request.
