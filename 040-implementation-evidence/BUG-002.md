# BUG-002 implementation evidence

## Scope and safety boundary

BUG-002 was an accepted file-only remote request whose target had actually
allocated, queued, and started a command, but whose incomplete lost boundary
could not be projected into a terminal mailbox result. The original Logger
side effect remains unknown. Its request ID, idempotency key, and script were
never replayed during this repair.

The correction comprises three commits on `dev`:

| Commit | Change |
| --- | --- |
| `81096fd` | Bounds the Mac projection of an unreadable remote terminal status. |
| `6de5004` | Adds explicit no-replay recovery of one retained lost runtime: durable runtime proof, atomic paired capacity release, then ownership finalization. |
| `519b4d9` | Accepts a systemd cgroup that was removed after a clean `inactive` stop, while retaining the stricter guard for a `failed` service. |

The recovery command accepts both the exact session and command IDs. It
requires a stopped `runnerd.service`, a terminal `lost/lost` record, the final
`command_lost` event, no sibling nonterminal command, and exactly one retained
slot/reservation pair. It never starts an agent or replays stored script bytes.
Capacity remains retained if runtime cleanup cannot be proved.
