### Planned implementation and gates

1. Add `runner exec SESSION_ID -- SCRIPT` using the same explicitly selected endpoint, with a stable idempotency key and durable acceptance ID displayed before output following.
2. Add `runner events COMMAND_ID [--after SEQUENCE] [--follow]`; command output records are written as raw bytes to their original stdout/stderr streams. Acceptance, lifecycle, and status/completeness metadata go to stderr so the CLI does not mix labels into stdout command bytes. Follow reconnects only from the last fully rendered contiguous event cursor.
3. Render command state, command exit code, event cursor/final sequence, `output_complete`, `output_truncated`, and `output_unavailable_reason` distinctly. A shell command failure is reported as the command's terminal exit/result; API/transport/protocol failures remain Runner errors. Incomplete or gapped history is never presented as a complete log. For expired history, show the server's incomplete status and earliest retained cursor; any retained-tail suggestion remains explicitly incomplete.
4.
