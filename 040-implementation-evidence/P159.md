# P159 — Workspace-compatible mailbox ingress

**Status:** PASS — 2026-09-30. This phase follows P158 and implements the
approved direct-file compatibility contract. It does not change configured
roots, target-selection policy, remote-host onboarding, direct mTLS, or the
software-crash-only durability boundary.

## Objective and selected contract

The user needs a workspace integration to create a file-only mailbox request
and acknowledgement at the normal workspace-created mode `0644`. P159 accepts
exact `0644` **alongside** the existing exact `0600` only for client-controlled
members of an existing `0700` mailbox tree:

```text
inbox/<request_id>.json
inbox/<request_id>.ready
acks/<request_id>.json
acks/<request_id>.ready
```

The native `mailboxclient` remains unchanged and continues to publish `0600`
files with exclusive creation, no-follow handling, file sync, directory sync,
and JSON-before-empty-marker ordering. Runner-created `outbox/*.json`,
`events/*.ndjson`, and projection temporary files remain exact `0600`.

The `0644` compatibility path still requires complete JSON before the empty
`.ready` marker. It does not claim the native publisher's exclusive-create,
no-follow, sync, or crash-durability properties. Every mailbox root and child
directory remains current-user-owned `0700`; no config, secret, database,
socket, script, output, or event-file permission is relaxed.

(`phase(P159): allow workspace mailbox ingress`). It separates validation of
client-controlled ingress from Runner-produced projections:
