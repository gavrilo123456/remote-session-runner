## Bounded P151 contract

1. Replace the Router's singleton queued remote caller with a profile-aware,
   immutable resolver built only from P150's configured remote profiles.
2. Select the pinned caller from the target profile persisted on each remote
   intent. Dispatch, same-key retry, uncertainty reads, session/job/command
   reads, event replay, terminal-gap confirmation, accepted-work recovery,
   and health probes must use that profile. Missing or unhealthy profiles fail
   their own work and never use another profile.
3. Preserve the restricted SSH transport: account `ubuntu`, no SSH config or
   agent, no PTY/forwarding, owner-only dedicated key, and pinned known-host
   file. The bridge host and port come only from the validated P150 registry.
4. Keep version-one behavior through its synthesized `linux-host` profile.
   Current callers and tests may retain a compatibility constructor only if it
   maps strictly to that legacy profile and cannot become a general fallback.
5. Make direct mTLS endpoint profile lookup use P150's named endpoint registry
   and retain its bound target profile. A direct CLI create/run with an
   explicit remote target must reject a mismatched `--endpoint` profile before
   a request is sent. Resource reads use their explicitly selected endpoint
   and retain the existing target-authority validation.

## Implementation and review

The Router now owns an immutable `RemoteCallerResolver` instead of one
singleton queued caller. Its defensive-copied profile map selects the caller
only from the remote target stored with the intent. Dispatch, same-key retry,
uncertainty reconciliation, session/job/command reads, event replay, terminal
gap confirmation, accepted-work recovery, and per-profile ping probes all use
that exact selection. A missing route fails before a lease or target call.
During a scheduler sweep, an unavailable profile remains recorded for repair
but cannot starve a later eligible configured profile or fall through to it.

The legacy constructors remain strict adapters for the synthesized v1
`linux-host` route. The Mac composition creates each queued SSH caller from
the validated profile registry using account `ubuntu`, the configured host and
port, its owner-only key, and its pinned known-host file. It does not construct
a queued caller for a direct-only profile. Per-profile health snapshots expose
one safe check per queued profile, so a successful host cannot hide another
host's failure.

Direct endpoint resolution now constructs the HTTPS client and its target
binding from one validated endpoint profile read. The CLI checks that binding
before `session create` or `run` sends a mutation, then rejects a contradictory
accepted target. This prevents a configuration change between separate client
and binding reads from sending a request to the wrong host.

The public event-mirror lookup was also corrected to recover the durable owner
of either a `submit_command` or a one-off `run` by command ID and controller.
It rejects ambiguous bindings and preserves controller isolation; it does not
reintroduce an unbound stream caller.

An independent final review found two initial defects: a missing route could
head-of-line block a valid profile, and direct client construction and binding
could observe separate configuration reads. Both were fixed before the final
gates. No remaining P151 blocker was found.
