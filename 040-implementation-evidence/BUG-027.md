# BUG-027 — Supported retained-work metadata inventory

## Scope

The correction extends the existing `runner-lane catalog-work-inventory`
command with `--details`. It does not add a daemon, schema, live service
upgrade, recovery action, ACK, replacement request or automatic safety verdict.
The default aggregate report and promotion inventory/hash contracts are unchanged.

The metadata reader supports the explicitly qualified schema-40 authority and
its migration history. It returns one bounded deferred SQLite read cut across
mailboxes, including active/queued/resumable work, held session reservations and
command slots, retained pairs (including commandless and completed-command
shapes), pending finalizations, and separately labelled local/remote intents.
Only scalar identity/state/cleanup/provenance metadata is selected. It never
reads scripts, output payloads, environment values, credentials or mailbox
response bodies to discover identities.

The native owner-only integration validates the fixed host/lane/configuration,
private database and pre-existing WAL/SHM identities, selected release/bundle,
schema and diagnostic build revision. It rechecks binding identities and
service state after the read. Missing data, incompatible schema, errors, drift
or bounds fail without partial identity rows. A successful export always says
`safe_to_resume=not_established` and `recovery_authorized=false`.

SQLite SHM reader coordination can update lock bookkeeping. The export makes
no application data/schema/WAL/runtime artifact mutation, and refuses missing
WAL/SHM before opening rather than create sidecars. No immutable SQLite mode
or service stop is used.
