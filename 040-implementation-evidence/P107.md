### Known design limitation

The detailed design §4 says direct create returns its 202 after durable authority acceptance and before the session reaches `ready`. The existing shared `execution.Service.CreateSession` currently performs runtime prepare/start synchronously before returning, so this adapter's HTTP response is emitted after that call returns (normally `ready`, or a recorded terminal outcome). P107's bounded gate does not include asynchronous timing, and the integration test records the current `ready` response. This is not evidence that the asynchronous-before-ready API contract has been met; resolve or explicitly clarify it before claiming full `I-01`/`P-CLI-01` acceptance. No second execution path was introduced.
