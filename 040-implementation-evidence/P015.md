## P015 deliverable

Make the existing `exec_idempotency` table a reusable mutation boundary rather than a create-session-only helper:

1. Add generic controller/operation/key lookup, expiry, same-hash replay, changed-hash conflict, and durable record helpers. The key namespace remains `(controller_type, controller_id, operation, idempotency_key)` and comparisons use the versioned canonical hash.
2. Apply that helper to session creation and command acceptance. A same-key/same-hash command retry returns the original command ID and durable snapshot without a second command/event/ordinal; a changed hash returns `ErrIdempotencyConflict`. Keys and hashes survive WAL reopen for their retention window.
3. Keep resource acceptance atomic: command idempotency row, command row, and sequence-1 `command_queued` event commit together. Expired mappings may be reused, but a live reservation/resource is never released by key expiry.
4. Keep P016’s stronger contiguous-order/eligibility rules and P017’s general event append/replay outside this phase. Do not add cancel/close resource implementations yet; the generic helper must be usable by those later mutations.

## Required focused gates

- same-key/same-hash replay returns the original ID/hash for session and command mutations, including after database reopen;
- changed semantic hash conflicts without a second resource, ordinal, reservation, or event; expired keys can be reused while existing resources remain;
- concurrent duplicate command acceptance produces one command/event and no duplicate execution hook;
- focused P011–P015 store tests, race-enabled P015 tests where applicable, full `make test`, `make vet`, selected-toolchain gofmt, and `git diff --check`;

- no host-dependent or Runner application TLS test is assigned to P015. P143’s software-crash-only durability path still requires explicit user approval if physical power-cut tests are unavailable.
