### P122 implementation and test plan

1. Keep the active idempotency guarantee at 90 days and the existing 30-day output-expiry behavior. Record compact expired-key fingerprints so a caller reusing an old key can be warned even after idempotency rows are collected; this history only signals prior key use and does not restore deduplication or permit retry claims.
2. Propagate that warning through direct HTTPS mutation acceptance for session create, command submit/cancel, session close, and one-off run. Extend the common client model and render the warning on CLI stderr so raw command stdout remains unchanged. Preserve the existing mailbox warning contract and verify it alongside these paths.
3. Keep Router retry cutoff at the persisted local-key expiry; test pre-expiry same-key retry and at/after-expiry no-mutation retry. No operation is redirected or given a replacement key.
4. Add fake-clock P122 tests for expiry, response warning, duplicate replay, migration/GC, CLI output, mailbox warning compatibility, and Router cutoff. Then run the focused P122 tests, full hermetic suite, vet, build, smoke, affected package race checks, `D-12` import boundary, migration checks, formatting, and `git diff --check` on Mac and Ubuntu. Ubuntu validation runs sequentially with its existing Go cache to avoid the cold-cache memory pressure recorded in P121.

The P122 checks are hermetic contract tests on each named development host; they do not claim a new live Runner application route or close P124's real-host CLI gate. No unrelated files or in-progress work were included in the P122 implementation commit.

### Implementation progress

- Added schema migration 0020. Expired direct-mutation key history is kept as a SHA-256 fingerprint scoped by controller and operation for one additional 90-day metadata-retention window. It contains no raw key or old request/resource binding; expiry warning history never restores the previous deduplication guarantee.
- Removed the `exec_jobs` unique controller/key index and replaced it with a non-unique lookup index. The idempotency table remains the authority for the bounded key guarantee; retained job metadata no longer blocks a new mutation after the key expires.
- Added the optional `idempotency_warning` enum to target-authority create, submit, cancel, close, and run acceptance responses. The common client validates the value and the CLI prints the warning on stderr, leaving command stdout unchanged. The mailbox response-file warning path is unchanged and remains covered by its P096 tests.
- Added P122 tests for expiry fingerprint/GC retention and cleanup, all five direct mutation acceptance paths after GC, client warning validation, and CLI stderr placement. Focused tests and all required Mac and Ubuntu gates passed; results are recorded below.
- The warning marker is deliberately bounded: after its additional metadata-retention window is garbage-collected, later reuse cannot be recognized and no warning is emitted. This does not extend the 90-day idempotency guarantee.
