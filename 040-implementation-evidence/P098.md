## Implementation approach and assumptions

- Extend the mailbox `SessionOperations` adapter with keyed cancel/close intent acceptance and exact-key status reads. The file client remains file-only; operations continue through the Mac Local API boundary.
- Refactor the existing Unix API cancel/close acceptance logic into shared helpers so mailbox and Unix ingress use the same controller lookup, payload validation, canonical hash, idempotency, and local-intent transaction.
- Keep a mailbox response `accepted` while its target intent is `recorded`, `dispatching`, or `uncertain`. Complete cancel only when the cancel intent is confirmed accepted/reconciled or the dispatcher proves the command was not delivered before cancellation. Complete close only after an authoritative terminal session/teardown result, or a proven never-created session (`not_created`). A definitely undelivered control request against a still-live target is rejected. No command/session state is synthesized from local intent alone.
- The frozen mailbox request schema represents optional `close_policy` as an object; the existing Unix API accepts a policy string. This slice maps the object's `policy` string to the existing API policy field, defaults omission to the existing `cancel` policy, and rejects unsupported object fields. It does not claim that a stored policy has already been executed by the target.
- Read-only and transport outcomes remain distinct; queued-remote uncertainty is left pending for later reconciliation. P103 owns the full uncertainty-deadline/`indeterminate` matrix.

## Implemented slice

- Added mailbox parsing/schema support for `close_policy`, defaulting omission and an empty policy to `cancel`. Unknown policy-object members are rejected.
- Normalized close-session receipt payloads and hashes using the effective policy. This makes omitted policy and explicit `{"policy":"cancel"}` the same idempotent request while a changed policy conflicts.
- Extracted shared Local API acceptance helpers for cancel and close so the Unix API and mailbox use the same validation, canonical payload, controller-scoped idempotency, and durable intent transaction. Existing Unix API error codes remain unchanged.
- Added exact controller/operation/idempotency-key intent lookup for status reconciliation. The mailbox does not use the latest intent for a resource when multiple control keys exist.
- Added mailbox cancel/close request handling and reconciliation. Accepted delivery is not presented as command cancellation or session teardown; uncertain delivery remains accepted; proven non-delivery and the original submit/create delivery determine only the designed no-op/rejection outcomes. Direct-created resources without a Mac local intent are denied.
- Added focused assertions for cancel and close replay, changed-policy conflict, uncertain and proven-not-delivered cases, target terminal state, never-created session, direct-created resource denial, and response/request schema shapes.
