## Gap and planned P111 work

Existing tests cover one-off retries and several in-process checkpoints. They do not yet exercise the complete I-04 restart matrix by closing and reopening the WAL database after each durable boundary: job-row acceptance, session commit, command acceptance, and teardown commit. Existing local API tests read a job while it is merely recorded, but do not GET a job after the Router has marked its queued intent `not_delivered`.

P111 will add:

1. An `I-01` operation contract fixture for direct HTTPS create/read, submit/read, cancel, close, and run/get-job, with remote-only target and mapped-controller behavior.
2. The matching Unix API resource-operation subset for local intents, checking stable resource-ID correlation and that local acceptance does not claim target authority.
3. An `I-04` WAL close/reopen matrix at all four durable barriers. It will assert unchanged job/session/command IDs, exact script bytes, one command start and runtime invocation, retained command/output result, and the actual teardown result.
4. A Unix API GET after a queued run reaches `not_delivered`, asserting that the response contains only the retained local intent outcome and that no authoritative job/session/command rows were created.

The direct HTTPS tests remain hermetic and do not access `129.151.232.40:8443`; P117 owns public TLS, certificate/IP-SAN, and authorization testing. The future P143 software-crash-only durability path remains subject to explicit user approval if physical power-cut tests are unavailable; no approval is assumed.
