### Planned implementation and gates

1. Add a reusable `src/internal/runnerclient` package with explicit Unix-socket and HTTPS constructors. The transport is fixed by constructor/client instance; session, command, and job IDs are opaque path values and cannot change or select ingress.
2. Provide typed mutation acceptances, typed session/command/job snapshots, a structured API error preserving HTTP status/code/retryability/resource/details, and command events that preserve command identity, sequence, timestamp, optional ordinal/output bytes/exit code, plus a cursor-aware streaming interface.
3. Support the shared v1 resource operations needed by the CLI: create/read session, submit/read command, stream command events, cancel command, close session, run/read job. Keep request paths, `Idempotency-Key`, query cursor/follow semantics, JSON envelopes, and NDJSON event framing aligned with both existing APIs.
4. Configure HTTPS explicitly with caller-provided roots and client certificate, TLS 1.3 minimum, no proxy inheritance, no redirects, and no silent endpoint fallback. Validate endpoint URL at construction. Unix uses only the selected absolute socket path.
5. Add package contract tests against an actual temporary Unix socket and an `httptest` TLS server with generated in-memory mTLS credentials. Run the same resource/error/event checks through each transport. Reuse identical opaque IDs across clients and assert each request reaches only its explicitly selected server. Assert event cursor continuity and rejection of wrong command identity, sequence gaps, malformed base64, and typed `410` event-history errors.
6. Run focused client tests, full Mac `make test`, `make vet`, `make build`, `make smoke`, relevant race tests, and `git diff --check`; inspect the complete diff. ### Unresolved assumptions

- The server resource envelope differs between local intent/projection and HTTPS authority snapshots. Typed resource structures must model fields shared across these documented variants and preserve optional variant fields without discarding useful data.
- The HTTPS transport constructor will require caller-supplied trust roots and client certificate rather than loading secrets, reading environment variables, or selecting endpoint from resource identifiers; endpoint profiles and CLI credential-loading behavior belong to later phases.
- The client provides context cancellation and returns the last delivered event cursor with stream errors; it does not claim to repair event gaps or infer missing events.
