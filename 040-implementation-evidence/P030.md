## Planned deliverable and gates

1. Define a versioned, length-prefixed JSON control frame with a strict 64 KiB body bound and no unknown fields or trailing JSON.
2. Require session ID and generation on every frame, bind parsing to the expected immutable pair, and reject stale generation/session frames before callers treat them as control.
3. Reserve distinct descriptors outside stdin/stdout/stderr and keep the parser on a dedicated control reader so printed stdout markers cannot spoof completion.
4. Exercise handshake, command terminal frames, wrong-generation rejection, marker spoof rejection, strict JSON, descriptor validation, oversize prefixes, and fuzzed bounds.

Required gates: focused P030 tests and fuzz run, store/execution regression tests, full `make test`, `make vet`, `make smoke`, selected-toolchain formatting and `git diff --check`, and the full race suite. No host-dependent runtime, SSH, HTTPS, mTLS, or Runner application test is assigned to P030. P143's software-crash-only durability path still requires explicit approval if physical power-cut tests are unavailable.
