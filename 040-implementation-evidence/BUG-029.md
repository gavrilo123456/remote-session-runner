## Implemented behavior

- Accepted run and submit observations each receive a default **15-second
  aggregate I/O budget per intent**. Run and submit batches have independent
  **15-second I/O budgets**.
- The driver carries aggregate deadlines as private context metadata. Only
  allowlisted read-only status calls and event streams derive actual deadline
  contexts. Mutation calls retain their original contexts and uncertainty
  rules; the observer budget never becomes an execution timeout or retry.
- Parent cancellation or its elapsed deadline takes precedence over an
  observer timeout. An expired observer cannot accept a late successful reply.
  Status-failure and stale-projection bookkeeping retain the live parent
  context, while stream event persistence uses the derived read context.
- Reconciliation cursors advance through the last attempted intent. Batch
  expiry leaves unattempted records eligible for the next pass, avoiding
  starvation behind a fixed prefix.
- SSH caller cancellation closes both parent pipe ends, releases blocked
  writes/reply/EOF reads, reaps the direct SSH child, and joins its cancellation
  callback. Stderr is connected directly to the null device, avoiding an
  internal copy goroutine that could wait on an inherited descriptor.
- Reply identity, EOF and exit-status checks, strict target observations,
  contiguous retained events, terminal proof and teardown requirements remain
  intact. An observation failure cannot manufacture an execution failure,
  replay, replacement identity or ACK.

These are remote-I/O budgets, not a claim that every SQLite operation or an
entire service cycle completes within 15 seconds.
