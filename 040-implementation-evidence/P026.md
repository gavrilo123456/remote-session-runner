## Implementation results

**Status: PASS**

- Extended the durable job checkpoint with teardown state/reason and command outcome fields. The checkpoint transaction preserves the exact command state, exit code, final event sequence, truncation, and completeness while advancing the coordinator phase.
- Completed `RunJob` through the shared keyed `CloseSession` path. A confirmed close records `closing_session` → `complete` with `teardown_state=closed`; an unconfirmed stop records `closing_session` → `lost` with `teardown_state=lost` while retaining the command result.
- Made the keyed close path restart-safe while a session is already `closing`: the same derived close key resumes teardown, and a job whose close transaction committed before its checkpoint only records the final job result without rerunning the command or stop.
- Added `I-04` teardown tests for successful command/close, nonzero command outcome, forced teardown failure, same-key retry, stable IDs, and restart after the close commit. Existing P025 tests were updated to assert the now-complete one-off lifecycle.
