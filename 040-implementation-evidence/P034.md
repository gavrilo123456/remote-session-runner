## Planned deliverable and gates

1. Apply a default 100 MiB combined stdout/stderr retention limit, with a test-configurable lower cap.
2. Retain only the raw prefix through the cap, emit one truncation indication, and continue draining/discarding all later bytes so Bash cannot block on a full pipe.
3. Keep the normal completion/EOF barrier and allow the same clean shell to run another command after truncation.
4. Exercise a 200 KiB output stream against a 64 KiB cap, exact raw-prefix retention, chunk bounds, exactly one truncation indication, continued drain, and post-cap command execution.

Required gates: focused P034 tests, store/execution regression tests, full `make test`, `make vet`, `make smoke`, selected-toolchain formatting and `git diff --check`, and the full race suite. No host-dependent SSH, HTTPS, mTLS, or Runner application test is assigned to P034. P143's software-crash-only durability path still requires explicit approval if physical power-cut tests are unavailable.
