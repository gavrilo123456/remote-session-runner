## Implementation results

**Status: PASS**

- Added `RunJob` and `ResumeJob` to the shared `ExecutionService`. The coordinator derives bounded deterministic create/submit step keys from the stable job ID, reuses the stored session and command IDs, and advances `creating_session` → `accepting_command` → `awaiting_command` only after the underlying shared-service transaction succeeds.
- Added `ResumeCommand`, which starts only a queued durable command and uses its stored exact script bytes. Running, terminal, and duplicate command states are returned without sourcing again.
- Added atomic `AuthorityStore.CheckpointJob` with expected-phase conflict protection and durable command outcome fields. A repeated checkpoint is idempotent; a stale worker cannot move a job backward.
- Added `I-04`/`D-16` fake-runtime tests for normal one-off execution, same-key retry, stable create-step resume, SQLite close/reopen after session acceptance, command acceptance before dispatch, exact script bytes, and no second source.
