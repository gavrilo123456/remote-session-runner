## Implementation

- Added `RemoteDriver.ReconcileIntent`, which issues only the existing bridge `get_session`, `get_command`, or `get_job` read operation for a remote intent in `dispatching` or `uncertain` state.
- A matching stable resource and immutable command checks (session ID, ordinal, and persisted script SHA-256) transition the intent to `accepted`. An explicit `resource_not_found` response proves `not_delivered`.
- Transport failures, protocol mismatches, mismatched resource data, and other non-terminal read errors leave the intent `uncertain`. Reconciliation never resubmits the mutation or allocates a replacement resource ID.
- Before-send mutation failures remain `not_delivered` and do not trigger a target read; after-send failures are reconciled through the stable resource identity.
