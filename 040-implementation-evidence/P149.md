## Fresh-context and implementation review

Before the repair, the current initial design, detailed design, phased plan,
preimplementation decisions, root `AGENTS.md`, current P148 evidence, mailbox
and operations documentation, store/dispatcher/local API/runnerd/runner-local
code, and the existing host deployment scripts were read. The repair was
independently reviewed for proof-marker correctness, mutation boundaries,
legacy recovery, deployment ordering, and the projected-cleanup interaction.
No production blocker was found.

The implementation provides these boundaries:

1. Remote `run` and `submit_command` mutation replies are acceptance-only.
   They cannot create a trusted remote job or command projection.
2. A restart reconciles accepted remote work through strict remote job,
   command, and event-stream reads. It never re-sends the original script,
   mutation, or idempotency key.
3. A durable `remote_terminal_proof_version` marker is written only after a
   consistent terminal target snapshot and event boundary are validated.
   Local API and mailbox terminal projections are withheld until then.
4. Terminal mailbox response/event recovery rebuilds only missing derived
   artifacts from the durable receipt. Existing previously published artifacts
   remain immutable.
5. Accepted-run recovery rotates its durable cursor so a bounded scan cannot
   starve later terminal work behind older active items.
6. Legacy terminal receipts with a raw `NULL response_cleanup_at` are read
   through their derived retention deadline before artifact recovery. This
   covers rows written before the cleanup-deadline migration without applying a
   backfill migration.

Migration `0024_remote_terminal_proof.sql` raises the schema to version 24 and
initializes historic remote intent proof versions to zero, so old accepted
records remain withheld until strict reconciliation supplies proof.

## Controlled `runner-local` crash proof

The final proof started only after the Mac reported `remote_router=ready`, zero
accepted mailbox exchanges, zero inbox markers, zero mailbox backlog, and the
Ubuntu P128 gate and permanent bridge status both passed.

- The request was published through `mailboxclient.WriteRequest`, not shell
  redirection. That client performs exclusive owner-only JSON creation, file
  sync, empty marker-last creation, and inbox-directory sync.
- The harmless remote script wrote a unique start marker, slept 180 seconds,
  wrote a unique end marker, and ran `uname -a`.
- Request: `req-p149-crash-9ec8cc61a2e34d129fbb2b87533b1e2d`.
- Job: `job-4f42391eed0ea5b52ff9ca4c0835cbcb`.
- Command: `cmd-718d387b8c32c0319b4f1e307f393652`.
- The test waited through `recorded` and `dispatching` until the durable local
  intent reported `delivery_state=accepted`, then waited two seconds. It
  verified that launchd PID `31476` was the installed
  `.../bin/runner-local` executable before sending `SIGKILL`.
- No installer, `bootout`, `kickstart`, socket removal, or second mailbox
  request was used after the kill. LaunchAgent `KeepAlive` restarted the
  service automatically as PID `41254`, and its private readiness report again
  showed `remote_router=ready`.
- The original response reached `complete` with the same job/command IDs,
  `delivery_state=reconciled`, `command_state=succeeded`, exit code zero,
  `output_complete=true`, `output_truncated=false`, and
  `teardown_outcome=closed`.
- The frozen event file had exactly six contiguous events. The unique start
  marker and unique end marker each occurred exactly once in both stdout and
  the event stream. `final_event_sequence=6`.
- The durable intent finished as
  `delivery_state=reconciled`, `attempt_count=1`, and
  `remote_terminal_proof_version=1`. The unchanged attempt count and one
  marker pair prove that recovery observed the original target work instead of
  executing a second remote `run` mutation.
- The terminal response was acknowledged through
  `mailboxclient.WriteAcknowledgment`; its ACK marker was consumed. No manual
  mailbox file redirection was used in this proof.

Two preliminary harmless long-running requests were completed and acknowledged
without a `SIGKILL`: one waited for a mailbox presentation state that P149 no
longer exposes before terminal reconciliation, and one treated the transient
`dispatching` intent state as terminal. They are not used as crash evidence.
The final proof above uses the actual durable target-acceptance boundary.

- Ubuntu `make test-p128-host-status` passed after the proof with all four

- Temporary mailbox-client helper sources were removed when their processes

- This validates a **software process crash and automatic restart**. It does
