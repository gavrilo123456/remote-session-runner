## Scope and planned gate

P114 adds `follow=true` to the direct HTTPS event route using the existing bounded register-before-replay store subscription. The stream ends after a terminal event or when overflow closes the subscription. It must drain any already-buffered events before ending and expose the last complete event frame written as a resumable cursor; the client resumes with `after=<cursor>&follow=true`. Finite replay remains unchanged. P113's `follow=true` invalid-query assertion is updated because that parameter is now supported.

Planned evidence is a deterministic direct-handler test that commits live events after replay has completed but before the handler drains the subscription, plus a slow-writer overflow test that verifies the reported cursor and gap-free resume through the terminal event. ## Assumptions and boundaries

- The resumable transport cursor is `X-Runner-Last-Sequence`: a normal response header for finite replay or a follow already complete at the supplied cursor, and a declared HTTP trailer for a live follow. On overflow it reflects the last full NDJSON frame successfully written, not events merely queued in the subscriber buffer.
- Direct follow uses the existing fixed 256-event subscriber capacity already used by the private/local follow adapters; P114 does not change the shared execution or event schema.
- Full three-path replay/follow, queued-remote mirror gaps, capture-loss and expiry qualification remain P115. Public endpoint, actual TLS identity authorization, and two-host network evidence remain P117.
- P143's physical power-cut gate and explicit approval requirement for a software-crash-only durability claim remain outstanding future gates; this preflight does not mark them passed.

## Implementation

The direct event route now accepts strict `follow=true`/`follow=false` values. Follow calls the shared controller-checked subscription before committing HTTP success headers, streams replay and live events in sequence, flushes each complete NDJSON frame, and stops at a terminal event or a closed bounded subscription. If the subscriber overflows, the handler drains the queued prefix before ending and reports the last fully written sequence in the `X-Runner-Last-Sequence` trailer. A client can resume with that cursor. Finite replay and a follow request already complete at its supplied cursor report the cursor in a normal response header. The OpenAPI event response documents the cursor contract. P113's old negative `follow=true` assertion now rejects malformed boolean values instead.

The P114 tests use a loopback `httptest.Server` and temporary SQLite authority. One hook commits output and a terminal event after the replay query but before delivery starts, proving the subscriber handoff has no sequence gap. A slow response writer pauses the stream until 257 new events exceed the 256-event subscriber capacity; the response drains exactly the 256-event buffered prefix, advertises cursor 258, and resumes at sequence 259 through the terminal event at 260. These are hermetic Runner application tests, not a public TLS/mTLS deployment test.
