## Intended repair and gates

1. Process independent mailbox records and inbox markers even when an earlier
   record cannot be reconciled or projected.
2. Preserve the existing durable remote-status-unavailable marker and its
   bounded, no-replay `indeterminate` terminal response for accepted remote

   diagnostics across a `runner-local` restart.

## Implemented repair

- Independent inbox markers, terminal-artifact recovery records, and accepted
  create, submit, cancel, close, and run records now continue in their
  deterministic order after one independent record fails. Each failure is
  returned as a safe structured reconciliation issue instead of preventing the
  rest of the cycle from running.
- Accepted remote one-off runs retain a durable status-read failure anchor and
  reconciliation-attempt count. The counter survives a `runner-local` restart,
  keeps the original bounded-deadline anchor, and never replays the accepted
  target mutation. The existing bounded `indeterminate` result remains the
  terminal outcome after the configured uncertainty window.
- `runner-local` now emits redacted, structured diagnostics. For a mailbox
  request it correlates the stable local intent with its durable receipt by the
  internal execution idempotency binding, then logs mailbox/request ID,
  operation, intent/job/session/command IDs, target profile, configured bridge
  endpoint, failure class, and retry count. It never renders a script, output,
  credential, key path, request payload, response body, or nested transport
  error.
- The repair deliberately leaves an accepted record with corrupt durable
  response bytes unresolved. There is no safe target outcome to invent from a
  corrupt receipt; it is retained and logged as `stored_response_invalid`, in
  accordance with the BUG-003 non-goal against deleting unresolved work.

## Closure and limits

BUG-003 is closed for the accepted remote one-off `run` reconciliation path.
An individual record failure no longer stalls later independent mailbox work,
and an accepted remote `run` status outage retains its existing bounded,
no-replay `indeterminate` result across restart with safe diagnostics.

An irreparably corrupt durable receipt remains deliberately unresolved and is
reported as `stored_response_invalid`. The repair does not invent a terminal
target outcome or delete that durable work. The live test is a new harmless
sandbox request; it does not retroactively prove any historic stalled request
or a physical power-cut durability claim.
