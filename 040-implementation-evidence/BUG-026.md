## Scope and result

One-off jobs used the same stateful sourced-shell command path as persistent
sessions. An explicit `exit` ended the parent before its command-complete
frame. BUG-015 deliberately preserved that behavior for persistent sessions;
BUG-026 gives disposable one-off scripts a separate child-shell boundary.

`ExecuteClaimedCommand` derives `RuntimeCommandRequest.OneOff` from the stored
job binding and validates its command/session identity. Missing jobs retain
persistent execution; other read failures and mismatches stop before runtime
execution. Both native adapters select the shared one-off method. That method
sources the original materialized bytes in a Bash subshell in the existing
owned process group, closes its control descriptors, then uses the parent's
existing completion and output-EOF barriers. Stored scripts/hashes, schema,
queue ownership, cancellation, cleanup and replay rules are unchanged.

Complete command output does not prove cleanup. If teardown cannot be proven,
the session reservation remains held. Actual parent death or unconfirmed
output stays lost. Persistent `exec` remains stateful and an explicit parent
`exit`/`exec` remains lost. No historical outcome is rewritten.
