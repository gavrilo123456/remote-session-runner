## P165 contract and required gates

After all existing file safety checks pass, malformed JSON, schema failure,
filename/request-ID mismatch, invalid script, or bounded-size failure must
create or reload only the P164 frozen diagnostic record. The processor must
atomically write `diagnostics/<request-id>.json` at `0600`, then revalidate
the input bytes/fingerprint and remove marker then JSON. It must not create an
exchange, intent, session, command, remote bridge call, Runner API call, or
workflow dispatch.

Recovery runs before ordinary unmarked-draft cleanup. It repairs a missing
active private artifact and completes only a safely revalidated matching input
cleanup. A retained rejected ID cannot become valid work. The only
correlation log fields are trusted mailbox/request ID plus fixed
`idempotency_key=unavailable`, `execution_target=not_selected`,
`remote_command_id=not_created`, `lifecycle_phase=ingress_validation`, and a
fixed failure class; no untrusted parser text or request content may be
logged.

Focused gates cover native `0600` and workspace `0644` malformed pairs;
unsafe inputs inert; zero-byte marker replacement; no durable execution
records/remote call; exact `0600` diagnostic; restart seams; duplicate/reuse;
adjacent valid work; cleanup/no-resurrection; bounded no-hot-loop behavior;
client decoding; and races. The full gate is focused tests, `make test`,
`go test -race ./...`, `make vet`, `make build`, `make smoke`, and
`git diff --check` on the Mac. P165 must be committed, pushed, and
fast-forwarded to primary Ubuntu before P166.

## Implementation and Mac validation

P165 adds a fifth private mailbox child, `diagnostics/`, and a durable,
redacted ingress-diagnostic path for safely admitted invalid input. Only a
safe JSON/zero-byte-marker pair can reach that path. The diagnostic is derived
from the P164 frozen record, written at exact `0600`, and is never a normal
outbox response or an executable request.

The importer rechecks marker authority after reading a request and uses
descriptor-backed identities plus hidden staging files for marker-first pair
cleanup. This retains a newer publisher replacement when it races with cleanup
instead of deleting its marker or JSON. Restart recovery removes only durable,
safe staging remnants before it examines the original pair. A retained
rejected request ID remains ineligible to become normal work.

The runner-local log has one fixed ingress-rejection line with the trusted
mailbox/request ID and fixed correlation values. It excludes parser text,
request bytes, scripts, idempotency keys, target selections, token material,
and private-key material. `mailboxclient` can only read frozen diagnostics; it
cannot publish or acknowledge them.
