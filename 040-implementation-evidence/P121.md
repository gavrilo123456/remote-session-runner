### P121 code and contract inventory

- CLI implementation and tests: `src/internal/runnercli/cli.go`, `cli_test.go`, `endpoint.go`, and `endpoint_test.go`. The CLI resolves one endpoint up front; `sessionClient` exposes session create/read, while `commandOperations` exposes command submit/read and P120 provides cursor-validated event streaming.
- The shared client already implements `CancelCommand`, `CloseSession`, `Run`, and `GetJob`; the existing API contract tests exercise their request/response IDs on Unix-socket and HTTPS transports. Cancellation is an idempotent request and does not promise terminal `cancelled`. Close acceptance acknowledges a request; confirmed session `closed` is observed by a later read. One-off run acceptance allocates stable job/session/command IDs, and `JobResource` exposes command result, output completeness, phase, teardown state, delivery, and failure reason.
- The local API may initially return a queued job intent with only delivery state and stable IDs. The CLI must not infer that the command ran or attempt to stream it before the selected ingress exposes an authoritative command state. For a job, command exit success alone is insufficient: failed/lost teardown makes the overall job unsuccessful.
- P120 `consumeCommandEvents` retains a contiguous cursor, writes raw stdout/stderr bytes to their respective streams, and reports transport/history errors without implying cancellation. P121 will reuse it for one-off command output. Existing fake resolver/session/command clients in `cli_test.go` will be extended for cancellation, close, job acceptance, and job snapshots.
- API semantics read from the versioned OpenAPI/schema and detailed design: close defaults to `graceful`; session `closed` is confirmed teardown, while `lost`/`failed` expose cleanup failure; job phases include `creating_session`, `accepting_command`, `awaiting_command`, `closing_session`, `complete`, `failed`, and `lost`; teardown states include `pending`, `closed`, `failed`, `lost`, and `not_created`.
- No live Runner application route is available from these hermetic tests. P121 does not claim full P-CLI-01, the Mac Unix-socket service, or public HTTPS application behavior; P124 owns common CLI smoke on local, queued-remote, and direct-remote routes.

### Planned implementation and gates

1. Add `cancel COMMAND_ID`, `session close SESSION_ID`, and `run --environment NAME --target local|remote --profile NAME -- SCRIPT`. All require an explicit `--endpoint`, resolve it once, preserve it through reads/events, and use an explicit or generated idempotency key. Print each retry key before its mutation and preserve accepted IDs after uncertainty.
2. Cancellation output describes request acceptance and currently known state only; it does not state that cancellation has completed. Session close waits within the global bounded wait timeout for `closed`, reports terminal cleanup failure, and retains the session ID on timeout/read failure.
3. One-off run displays job/session/command IDs as soon as acceptance is known, waits for authority/delivery before opening the command event stream, streams raw output through the P120 cursor path, and observes the job through teardown. It returns the command's shell exit code only after successful teardown; failed/lost teardown, event/transport errors, or bounded pending outcomes are distinct. Timeout and uncertain delivery never cause a second mutation with a new key.
4. Focused automated tests will cover cancel-request wording/endpoint/key, close success and visible lost teardown, run stable IDs/request fields and raw output, nonzero command exit, successful command with failed teardown, queued intent before authority, bounded timeout preserving IDs, and explicit-endpoint enforcement/direct-HTTPS target rules. ## P121 implementation and validation results

- Implemented top-level `cancel`, nested `session close`, and one-off `run`. Every mutation requires an explicitly chosen endpoint, uses an explicit or generated idempotency key printed before the request, and keeps resource IDs on stderr before command output. Direct HTTPS still rejects local targets. Cancellation is reported as a request with only the currently known state. Session close waits for `closed`/`expired`, reports `lost`/`failed`, and treats a proven never-delivered create intent as the explicit successful no-op outcome `not_created` without fabricating a target session state. The close timeout retains the accepted session ID and does not send a second close.
- One-off run preserves job/session/command IDs, checks every returned job identity against acceptance, waits for queued local intent to reach authority before opening the event stream, follows raw command output from cursor zero, and waits through teardown. It returns the shell exit only after a complete job with `teardown_state: closed`; failed/lost teardown remains a CLI failure even if the command succeeded. A wait timeout leaves accepted work running and gives the same-key retry path. A stream's own deadline remains a transport error unless the configured CLI wait deadline actually expired.
