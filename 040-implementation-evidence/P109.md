## Contract gap and resolution before implementation

The P109 plan requires a changed close-policy request using the same key to return an idempotency conflict. The detailed design describes `close_session` as accepting an optional close policy, and the shared execution request hashes that policy. However, current direct OpenAPI `DELETE /v1/sessions/{session_id}` documents no request body, and the existing direct handler has no close route. Existing private runnerd close input already uses an optional `policy` field and defaults it to `graceful`.

For P109, direct close will accept an optional JSON body containing only `policy`; an empty body and an omitted policy both mean `graceful`. The route ID, operation name, and effective policy will be included in the canonical idempotency request hash. The OpenAPI contract will document the optional body and its `policy` schema. This matches the existing private request shape and the detailed-design optional-policy contract, while making the plan's changed-policy conflict gate exercisable. The policy is currently an idempotency semantic input in `ExecutionService`; P109 will not claim distinct teardown behavior for different policy values.
