## B009-P2 result

**Passed source phase.** Commit `22d44ce4e4492bf932afcf15dbcda304e09b7992`
(`phase(B009-P2): recover retained lost capacity on dispatcher ticks`) adds a
bounded automatic path only after the normal dispatcher tick gets
`ErrCommandSlotsFull`. It reads only the P1 exact retained-lost candidate set,
performs existing process-group proof and the queue-preserving paired release,
then wakes the same dispatcher to claim the already accepted queued command.
It neither reads/replays a lost script nor creates a replacement request,
job, session, command, or scheduler.

The paired release now writes a durable pending-finalization row in the same
SQLite transaction. The row pins its command/session metadata until the owned
workspace/marker finalization succeeds. Startup finalizes those rows before
ownership audit; a failure blocks that startup safely. Dispatcher retries for
post-release finalization and retained-capacity proof use independent bounded
throttles, so a marker-cleanup failure cannot prevent later capacity recovery.
Migration `0032` intentionally does not reinterpret historical released-lost
rows that used the older reconciliation protocol.
