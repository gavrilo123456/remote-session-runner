### Findings and bounded scope

1. Direct HTTPS P113/P114 already supplies bounded NDJSON replay/follow, structured `410 event_history_unavailable`, and a resumable cursor. P114 tests prove handoff and a 256-event overflow prefix/resume. P115 will add direct status/error matrix assertions for all three output-unavailable reasons.
2. Mac local-authority follow in `localapi.Server.handleCommandEvents` currently returns as soon as `subscription.Errors()` fires, dropping any buffered prefix queued before overflow. It does not publish a last-complete-frame cursor.
3. Mac queued-remote follow in `handleMirroredRemoteEvents` polls only the durable local mirror and silently closes after post-header read failure; it has no cursor header/trailer. Initial remote gap/expiry uses the wrong status mapping (`416`) and the generic envelope omits `output_complete:false` and the specific unavailable reason, contrary to §4.2's `410` contract.
4. The existing mailbox P097 projection test matrix covers all O-03 reason distinctions and only advertises contiguous stored event prefixes; P115 will extend integration assertions where needed rather than change the mailbox reason model absent a failing test.

No plan/design ambiguity was found. The Mac Unix API is the same v1 route family as direct HTTPS; for a stream that fails after headers, the response must remain resumable and must not claim a terminal/complete history. The declared last-sequence header/trailer reports the last whole NDJSON frame written. Pre-header gap/expiry errors carry structured reason metadata.
