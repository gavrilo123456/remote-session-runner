B010-P1 adds a read-only classifier that uses only safe filename-derived
request IDs, `lstat` metadata, and a narrow AuthorityStore read transaction.
The store query selects only exchange state, acknowledgement presence,
diagnostic presence, and diagnostic input-pair-removal presence. It does not
load or expose request JSON, scripts, idempotency keys, responses, output,
credentials, headers, or key material.

`mailbox_backlog` now combines accepted durable exchanges with only safe,
complete, zero-byte-marker request pairs that have no durable exchange or
ingress diagnostic. It excludes marker-only, nonempty, unsafe, symlinked,
terminal, diagnostic, and another-inbox same-ID artifacts. Filesystem and
SQLite are necessarily sampled separately, so this operational metric is a
best-effort current snapshot; it is not an execution decision or a durable
audit query.

### Behaviour delivered

`DurableOrphanReconciler` runs only after normal request and ACK intake, and
only for a mailbox whose versioned configuration explicitly sets
`durable_orphan_cleanup: true`. The omitted/default value is `false`. This
keeps the existing SlideStudio residue intact while B010-P3 supplies a
read-only lifecycle view and an operator reviews it.

When enabled, the reconciler removes at most 64 proven hidden-stage or public
marker artifacts per cycle. A request marker requires an existing exchange or
a diagnostic whose input-pair removal is durable; an ACK marker requires a
durable acknowledgement. It never reads request or ACK bodies, deletes JSON,
response/event/diagnostic artifacts, calls `SessionOperations`, or invokes a
remote bridge.

Before removal, a public marker is safe-file checked, empty, paired-JSON
checked, moved to a same-directory hidden stage, rechecked, and directory
synced. A newer marker or JSON always wins. Interrupted hidden stages are
recovered only with the same durable proof; a staged old marker is retained
while replacement JSON is present without its own public marker, so it cannot
make that draft executable. Nonempty, wrong-mode, and symlink replacements
are restored at the public pathname without overwriting a newer path and stay
inert.

### Behaviour delivered

`GET /v1/mailboxes/{inbox_id}/lifecycle[?request_id=<safe-request-id>]` is a
Mac Unix-socket-only extension. It selects only a configured active inbox and
returns either a metadata-only lifecycle answer or a generic explicit
unavailable result. It is not in shared `openapi.json` and is never exposed by
the direct mTLS HTTPS listeners.

The result contains only the B010-P1 input-shape, durable-state, and action
labels; aggregate current artifact counts; a safe request ID when selected;
and derived terminal, acknowledgement, and ingress-diagnostic flags. It has no
filesystem-path argument. Unknown inboxes return `404 mailbox_not_found`,
malformed selection returns `400 invalid_request`, and an unavailable tree or
durable source returns `503` with `available: false` and
`mailbox_lifecycle_unavailable`. It does not infer a state from a missing or
lone marker.

The read path uses the existing configured-root lifecycle classifier and
narrow durable evidence only. It neither imports, reconciles, publishes,
executes, writes health/audit data, nor contacts a remote host. It never reads
a request or ACK body and cannot return scripts, payloads, idempotency keys,
outbox response/output, resource IDs, credentials, headers, keys, paths, or
raw store/filesystem errors.

The mailbox, operations, LLM-client, configuration, API, architecture, and
OpenAPI-scope documentation now describe the exact endpoint, normal
`request_id → outbox → command_id → events` correlation, durable ACK evidence,
truthful backlog meaning, retention limits, and explicit cleanup boundary.
