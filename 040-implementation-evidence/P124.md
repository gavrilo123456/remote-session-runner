## P124 remediation analysis — before additional source edits

The failing command is submitted through the Mac local API, which returns `acceptance_scope: local_intent` before the separate Router/locald target-acceptance step. The P124 harness starts the CLI and target dispatch concurrently. `runnercli.runCommandExec` immediately opens its follow event stream after that local-intent response; `localapi.handleCommandEvents` returns `404 command_not_found` if locald has not yet written the target command row. The queued-remote path has the analogous pre-acceptance `409 events_unavailable` response until the remote projection becomes eligible. This is consistent with the observed local failure and with the intended asynchronous acceptance boundary; the target command ID and intent are already durable.

Planned fix: make `exec` wait a bounded duration for target acceptance only when the CLI received `acceptance_scope: local_intent`. Retry only the two known pre-target responses (`command_not_found` and `events_unavailable`) at the existing readiness polling interval, then follow the accepted target stream as before. Honor global `--wait-timeout`; timeout must preserve the command ID, report resume instructions, and never cancel accepted work. Do not retry these responses for direct `target_authority` acceptance. Add CLI regressions for local and queued acceptance races and for non-retry of direct-authority errors, then rerun the synchronized P124 host gate.
