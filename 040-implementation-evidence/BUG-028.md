## Preventive source correction

The Mac replacement route detects other worker profiles referencing the same
server-CA path. It preserves the exact validated original CA bundle and adds
the validated replacement root only when absent by DER identity. An unshared
path retains replacement-only rotation. The existing journal records the
actual installed bundle digest without a receipt/schema-format change.

Retry planning uses the journal-bound immutable original backup. Legacy
destructive targets and an unbacked intent with changed current trust fail
before service stops or file writes. Normal file compare-and-swap, ownership,
mode, backup, work, selector and approval guards remain in force. Completed
live PRD bootstrap and the separate approved two-CA amendment are not replayed
or rewritten by this work.

The production entry point also rejects differently named CA paths that
identify the same physical file, including actual APFS case aliases. It
checks file identity, ownership, mode and link count before journal creation
and again under the lifecycle lock before writes. Separate files on a
case-sensitive volume retain normal unshared rotation.

This correction belongs to the installer/operator path. Its specific proof
uses disposable trust, backup and interruption fixtures, with the public
bootstrap CLI invoking the real trust planner through its test-only service
backend. Native backup/file-CAS and legacy journal guards are exercised in
the installer package. Dev/QAS service acceptance separately verifies the
new sealed release and lane isolation; it does not rerun live PRD bootstrap.
