## Implementation

- Added `run` to the Mac `LocalDriver` supported operation set. It still sends only the committed intent ID, request hash, and no caller payload through `LocaldClient`.
- Added `run` handling to `runner-locald`'s identity-only acceptance endpoint. It reloads the immutable local intent and calls the existing shared `execution.Service.RunJob` coordinator with the stable job/session/command IDs, canonical payload, exact script bytes, and policy fields. The response reports the durable job phase and target session/command states.
- The shared one-off coordinator therefore performs the existing durable `creating_session` → `accepting_command` → `awaiting_command` progression before its later teardown work. Retries reuse the same `exec_jobs`, session, command, and script bytes; no replacement resource or second source is created. The remote SSH bridge `run_or_resume_job` path already forwards these same stable IDs to runnerd and remains covered by P069/P077.
- Added focused tests for local Router `run` dispatch identity/replay and locald execution through stable checkpoints, including exact script-byte preservation and replay after completion. Updated the earlier local-driver fixture to reflect that local one-off runs are now supported while remote intents remain excluded.
