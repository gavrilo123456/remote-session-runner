## Scope and planned gates

P012 adds the version-2 SQLite migration for `exec_sessions` and `exec_session_lifecycle`, a concrete authority-store API for creating/reading/transitioning sessions, and target/controller-preserving records. Creation writes `state=creating` and lifecycle sequence 1 in one transaction. State transitions validate the shared D-01 session edges and write the new state plus its lifecycle row in one transaction. Target, profile, environment, and controller identity are immutable at the schema/store boundary. P012 does not add capacity reservations, idempotency, commands, runtime startup, or host services; those belong to later phases.

Focused P012 gates on the Mac are:

1. Store fixtures create local and remote sessions, reopen them, and verify target/profile, environment, controller type/ID, source, effective limits, timestamps, and runtime metadata survive exactly.
2. Atomic lifecycle fixtures verify create and every valid transition append one lifecycle record with the right previous/new state and reason; invalid transitions leave both current state and lifecycle history unchanged; an injected lifecycle-write failure rolls back the state update.
3. Existing P011 migration/open tests pass against the expanded migration list; the full `make test` suite, `make vet`, race-enabled P012 store tests, formatting, `git diff --check`, and complete staged diff review pass.
4. P012 has no real Runner process, service, Linux host, SSH, HTTPS, or physical-durability suite. Those remain `NOT RUN`, not PASS. The temporary mTLS probe remains transport-only evidence. P143 still requires explicit user approval for a software-crash-only durability claim if physical power-cut tests are unavailable.
