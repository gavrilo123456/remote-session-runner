## Recovery contract

The new explicit `--teardown-pair SESSION:COMMAND` is exclusive of lost-command
and commandless recovery selections. It accepts only an owner-matched local
one-off with a successful complete command, an already released command slot,
a lost job/session teardown and a retained session reservation. It requires
the complete idle authority, exact selected ownership, no queued/active work,
and no unselected retained capacity or pending recovery finalizations.

The runtime first records durable proof for the exact session generation.
One immediate transaction revalidates the entire selection, releases only the
session reservations, and records durable finalization work. Marker/workspace
removal follows the commit. Startup retries only this post-release work before
ownership audit; it never reproves/signals an old PID or executes script bytes.
Pending finalization protects its necessary metadata and event history from GC.
The original job/command/session outcome and event prefix stay unchanged.
