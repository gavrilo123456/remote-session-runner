## B008-P1 contract and planned gate

The existing offline `recover-lost` and `recover-stalled` operations remain
strict and unchanged. B008-P1 adds only a separate internal store/execution
scope which can prove and release a complete explicit set of terminal-lost
pairs while preserving unrelated ready sessions with queued work.

Before any capacity release, it must reject all of the following without
runtime invocation or durable write: an empty, duplicate, mismatched, partial,
or nonterminal selected pair; an unselected live command slot; a running or
cancelling command; an unsafe non-selected reservation; incorrect host; or a
preserved session/job/command identity that is not exactly ready/awaiting/
queued. Runtime cleanup proof remains required. A successful immediate
transaction releases only selected paired slots and reservations, retaining
queued job/session/command IDs, ordinals, idempotency keys, and histories.

The source gate is focused store and execution coverage for the four-retained
lost/two-preserved-queued fixture, all reject-without-write variants,
cleanup-proof failure, atomic rollback, and no-replay identity checks. The
full suite and race gates occur after B008-P2/B008-P3, when the concurrent
coordinator and projection are in place.

## B008-P4a — Installer cache reuse corrective follow-up

P6's initial preflight exposed an operational defect in the installers: each
normal service update created a fresh private Go module cache. The pre-restart
P128 status gate therefore spent time retrieving dependencies into a disposable
tree. Two task-owned installer processes were stopped before either reached a
build or service restart. The existing sandbox `runnerd.service` remained
active; no mailbox request, Logger workflow, or P6 acceptance result was
created.

Commit `90fc6eeadc89f9cba929da1ff70e428e9e8d5bc1`
(`fix(B008-P4): reuse Ubuntu Go caches`) removes that disposable-cache path
from both normal Linux update paths. The `runnerd` installer and its optional
queued-bridge refresh now reuse only the selected `ubuntu` account's normal
Go caches:

```text
/home/ubuntu/.cache/go-build
/home/ubuntu/go/pkg/mod
```

Neither installer changes permissions on or deletes those shared caches. The
P126 host gate snapshots both historic private-cache naming patterns before
and after an update, while static checks forbid either pattern in either
installer. Existing orphaned historic cache folders therefore do not make the
gate fail, but a newly persistent one does. The Linux and queued-bridge
runbooks now describe the same behavior.
